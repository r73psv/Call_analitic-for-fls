# ТЕХНИЧЕСКАЯ АРХИТЕКТУРА И ОПИСАНИЕ СИСТЕМЫ
## Интеллектуальная система речевой аналитики и контроля качества звонков салона красоты «Fashion Look Studio»
*(Версия 2.8 • Yandex SpeechKit • Сбер GigaChat • МегаФон ВАТС • 152-ФЗ РФ)*

---

## 1. Общие сведения и назначение системы

Система представляет собой программный комплекс класса **Speech Analytics & Quality Assurance (QA)**, предназначенный для салонов красоты и медицинских центров. Комплекс осуществляет непрерывный автоматический сбор входящих и исходящих аудиозаписей телефонных переговоров, их транскрибацию с разделением ролей собеседников, смысловой анализ с помощью нейросетей, оценку работы администраторов по стандартам сервиса, формирование списка следующих шагов (**Next Steps**), учет согласий на обработку биометрии по 152-ФЗ и экспорт управленческой отчетности (CSV, PDF).

### 1.1. Ключевые решаемые задачи
1. **Исключение потери лидов**: мониторинг всех входящих обращений, выявление отказов и причин срыва записи на ранней стадии.
2. **Контроль соблюдения стандартов сервиса**: автоматическая оценка звонка по шкале от 1 до 10 на основе вежливости, презентации услуг, предложения сопутствующих процедур и записи на повторный визит.
3. **Автоматизация рутины дежурного администратора**: ИИ-генерация конкретного чек-листа действий по итогам каждого разговора (внесение слота в CRM Yclients, отправка подтверждения и адреса в WhatsApp/SMS, заказ расходных материалов, постановка напоминания).
4. **Безопасность и 152-ФЗ**: сквозное маскирование номеров, защита персональных данных, реестр согласий на аудиозапись, шифрование хранилища (AES-256-GCM) и работа с российскими сертификатами безопасности.
5. **Своевременное реагирование на конфликты**: мгновенная фиксация претензий и отправка тревожных алертов руководству через VK Мессенджер / Telegram.

## 4. Механизм получения аудиозаписей и данных по обеим версиям АТС МегаФон

Система поддерживает работу с виртуальной АТС МегаФон в **двух взаимодополняющих режимах**:
1. **Версия 1 (Push / Webhook / CRM-протокол)** — передача данных со стороны АТС в реальном времени.
2. **Версия 2 (Pull / REST API / WCGP Polling)** — активный опрос и выгрузка истории со стороны системы.

Оба механизма могут работать одновременно (гибридный режим), гарантируя 100% сбор вызовов даже при кратковременных сбоях сети или недоступности вебхуков.

```
       ┌─────────────────────────────────────────────────────────────┐
       │                     ВАТС МЕГАФОН                            │
       └──────────────┬──────────────────────────────▲───────────────┘
                      │                              │
         [ВЕРСИЯ 1: Push]               [ВЕРСИЯ 2: Pull]
         HTTP POST Webhooks             WCGP / REST Polling
         (cmd=history / event)          (cmd=history / accounts)
                      │                              │
                      ▼                              │
       ┌─────────────────────────────────────────────┴───────────────┐
       │             CallQA Backend (Express Server)                 │
       │                                                             │
       │  1. Аутентификация токена (crm_token / token)               │
       │  2. Дедупликация звонков по UID / callid                    │
       │  3. Скачивание MP3-аудиозаписи (Direct Link / Reports API)  │
       │  4. Проверка длительности (> 10 сек)                        │
       └──────────────────────────────┬──────────────────────────────┘
                                      │
                                      ▼
                      [Конвейер обработки звонка ИИ]
```

### 4.1. Версия 1: Push-модель (Входящие вебхуки / Протокол CRM-интеграции)

В этом режиме АТС МегаФон выступает клиентом, который отправляет HTTP POST запросы на сервер системы сразу после наступления телефонного события.

#### Поддерживаемые эндпоинты в `server.ts`:
- `/crm_integration.php` (официальный путь по документации МегаФон);
- `/api/calls/webhook`;
- `/api/vats/webhook`;
- `/api/megafon/rest/webhook`.

#### Обрабатываемые команды (`cmd`):

1. **`cmd=history` (Завершение разговора и передача записи)**:
   - Отправляется АТС после окончания звонка.
   - Поля запроса:
     - `callid` — уникальный идентификатор звонка в АТС;
     - `type` — направление вызова (`in` — входящий, `out` — исходящий);
     - `status` — статус (`Success`, `Missed`, `Cancel`, `Busy`, `NotAvailable`);
     - `phone` — номер телефона клиента (например, `79991234567`);
     - `user` — логин или имя ответившего сотрудника;
     - `start` — дата и время начала разговора;
     - `duration` — общая длительность звонка в секундах;
     - `link` — прямая временная ссылка на скачивание MP3-аудиозаписи;
     - `crm_token` — токен авторизации для проверки подлинности запроса.
   - **Алгоритм работы сервера**:
     - Проверяется `crm_token`. При несовпадении возвращается `403 Forbidden`.
     - Звонок сохраняется со статусом `processing`.
     - Если статус `Success` и длительность более 10 секунд, инициируется фоновое скачивание аудиофайла по `link` и запуск конвейера транскрибации и анализа.
     - Ответ АТС отдается немедленно со статусом `200 OK`, чтобы предотвратить повторные ретраи со стороны телефонии.

2. **`cmd=event` (События жизненного цикла звонка в реальном времени)**:
   - Передает статусы: `INCOMING` (поступление звонка), `ACCEPTED` (снятие трубки), `COMPLETED` (завершение), `CANCELLED` (сброс).
   - При событии `INCOMING` сервер генерирует Push-уведомление администратору через веб-сокеты / внутренний канал событий для отображения карточки звонящего.

3. **`cmd=contact` (Всплывающая карточка в софтфоне МегаФон)**:
   - АТС запрашивает у системы информацию о звонящем абоненте по номеру `phone`.
   - Сервер выполняет поиск в локальной базе и возвращает JSON `{ "contact_name": "Ольга (постоянный клиент)", "responsible": "admin" }`.

4. **`cmd=rating` (Оценка разговора клиентом)**:
   - Передает оценку (1–10), если в АТС включен постопрос абонента через голосовое меню. Сервер обновляет поле `operator_score`.

### 4.2. Версия 2: Pull-модель (REST API / Протокол WCGP Polling)

В этом режиме сервер системы самостоятельно обращается к API ВАТС МегаФон по защищенному каналу. Данный механизм используется как для фоновой периодической синхронизации (раз в 5–15 минут), так и для ручной выгрузки звонков оператором.

#### Базовые адреса и автоматическое разрешение эндпоинтов:
Функция `resolveWcgpEndpoints()` в `megafonRest.ts` формирует каскад адресов:
1. `https://<domain>/sys/crm_api.wcgp` — официальный шлюз WCGP (Web Client Gateway Protocol);
2. `https://<domain>/crmapi/v1` — прямой REST-шлюз;
3. `https://<domain>/crmapi/v1/${cmd}` — path-based роутинг;
4. `http://<domain>/sys/crm_api.wcgp` — резервный вариант при неполадках SSL.

#### Поддерживаемые команды:

1. **`cmd=history` (Выгрузка реестра звонков)**:
   - Параметры: `period=today`, `yesterday` либо точные временные рамки в формате UTC: `start=YYYYmmddTHHMMSSZ&end=YYYYmmddTHHMMSSZ`.
   - Формат ответа: МегаФон возвращает данные в виде CSV-потока (реже JSON).
   - Заголовки CSV: `UID,type,client,account,via,start,wait,duration,record,quality_control`.
   - **Парсер `parseWcgpCsvHistory()`**:
     - Автоматически распознает разделители: `;`, `,`, `\t`;
     - Удаляет UTF-8 BOM (`\uFEFF`);
     - Корректно разбирает экранированные кавычки;
     - Преобразует даты вида `20261106T143000Z` в стандартизированный ISO 8601;
     - Если выгрузка за `today` вернула 0 строк из-за смещения часового пояса UTC, парсер автоматически повторяет запрос с точным диапазоном за последние 24 часа.

2. **`cmd=accounts` (Синхронизация сотрудников салона)**:
   - Возвращает список пользователей АТС: логин (`name`), ФИО (`realName`), добавочный номер (`ext`), мобильный (`telnum`).
   - Используется для автопривязки звонков к конкретным дежурным администраторам.

3. **`cmd=groups` (Отделы и очереди)**:
   - Выгрузка структуры очередей входящих вызовов.

4. **`cmd=makeCall` (Функция Click-to-Call)**:
   - Инициирует обратный звонок клиенту из браузера: АТС сначала дозванивается до администратора салона, а затем соединяет его с клиентом.

#### Механизм поиска и скачивания аудиозаписи:
Если поле `record` в выгрузке `cmd=history` не содержит прямой внешней ссылки (или содержит только внутренний ID отчета вида `/reports/mgf_calls/`):
1. Сервер вызывает функцию `getMegafonRecordingDirectLink(communicationId)`.
2. По протоколу внутренней отчетности АТС через команду `get.mgf_calls` запрашивается детальный отчет по сессии за интервал времени `[start - 5 мин, end + 5 мин]`.
3. Находится прямая временная ссылка на медиа-сервер МегаФон.
4. Ссылка кэшируется в базе данных, и бинарный поток MP3 загружается в память сервера.

### 4.3. Сравнение механизмов получения данных АТС

| Критерий | Версия 1 (Push / Webhook) | Версия 2 (Pull / REST WCGP) |
|---|---|---|
| **Инициатор запроса** | АТС МегаФон | Сервер речевой аналитики |
| **Скорость поступления** | Моментально (0–5 секунд после вызова) | По таймеру (раз в 5–15 мин) или по кнопке |
| **Требования к сети** | Нужен внешний доступ к серверу (белый IP / домен) | Работает даже за NAT / в изолированной сети |
| **События реального времени** | Поддерживаются (`INCOMING`, карточка контакта) | Не поддерживаются (только факт завершения) |
| **Устойчивость к сбоям сети** | При отключении сервера вебхуки могут потеряться | При восстановлении связи выгружает весь архив |
| **Роль в системе** | **Основной канал** онлайн-аналитики | **Резервный канал** и синхронизация архива |

### Детальное описание этапов конвейера:

#### Шаг 1. Предварительная валидация
Если звонок длился **менее 10 секунд** либо завершился со статусом `Missed` / `Cancel` / `Busy`, система **категорически блокирует** запуск нейросетей. В базу заносится отметка: *«Разговор не состоялся (длительность менее 10 сек). Оценка оператора не выставляется»*. Это исключает галлюцинации LLM на пустом аудиофайле.

#### Шаг 2. Загрузка и подготовка аудио
Сервер скачивает бинарный аудиопоток в буфер оперативной памяти. Файл проверяется на целостность. При необходимости транскодирования задействуется утилита `ffmpeg`.

#### Шаг 3. Транскрибация речи через Yandex SpeechKit
- Аудиопоток передается в Yandex Cloud SpeechKit с использованием модели распознавания русской речи `general`.
- Применяется двухканальная диаризация для четкого разделения реплик на стороны: `Менеджер:` и `Клиент:`.
- Модуль `transcriptUtils.ts` (`fixDuplicatedTranscript`) устраняет акустические артефакты, дублирующиеся фразы и эхо.

#### Шаг 4. Обезличивание текста по 152-ФЗ
Перед отправкой стенограммы во внешнюю языковую модель функция `anonymizeTranscript()` заменяет:
- Все телефонные номера клиентов на маскированный шаблон `+7(***)***-XX-XX`;
- Номера банковских карт и расчетных счетов;
- Паспортные данные и полные адреса проживания.

#### Шаг 5. Смысловой анализ Сбер GigaChat
Обезличенный текст передается в Сбер GigaChat с системным промптом, настроенным на салон «Fashion Look Studio». Модель возвращает строго валидированный JSON-объект:
- `booking_status`: `согласие` (клиент записался), `отказ` (клиент отказался), `консультация` (справочный звонок);
- `key_facts`:
  - `service`: конкретная услуга (например, *«сложное окрашивание AirTouch»*);
  - `date`: согласованная дата визита;
  - `time`: время записи;
  - `master`: имя выбранного мастера;
  - `promises`: обещания администратора (например, *«отправить палитру в WhatsApp»*);
  - `is_dispute`: маркер конфликтной ситуации (`true`/`false`) и `dispute_reason`.
- `transcript_summary` (4 обязательных структурированных блока):
  - **Суть обращения:** параметры записи (услуга, дата, время, мастер);
  - **Краткий пересказ разговора:** строго 2–4 предложения о ходе диалога;
  - **Вывод:** результат обращения (запись зафиксирована, отказ, консультация);
  - **Разбор работы менеджера (оценка X/10):**
    - *Ошибки и недочёты:* детальный разбор конкретных ошибок сотрудника, повлекших снижение оценки (пассивность при отказе, отсутствие альтернативных слотов, не предложены сопутствующие услуги, не названы цены или регламент напоминания);
    - *Советы по оптимизации:* практические советы по ведению диалога и продажам, составленные строго исходя из выявленных ошибок.
- `operator_score`: объективный балл (от 1 до 10) по регламенту сервиса;
- `operator_mistakes`: массив строк с конкретными недочетами менеджера;
- `operator_comment`: аргументация оценки аудитора;
- `recommendations`: перечень советов по оптимизации работы сотрудника.

#### Шаг 6. Генерация чек-листа «Next Steps»
Нейросеть (или специализированный эвристический генератор `generateLocalNextSteps`) формирует 3–5 практических задач для дежурного администратора:
- При согласии: внести бронь в CRM Yclients с фиксацией слота и мастера, выслать клиенту подтверждение и схему проезда в мессенджер, поставить напоминание за 24 часа.
- При отказе: проставить причину в базе, назначить рассылку персонального спецпредложения через 14 дней.
- При конфликте: зарегистрировать претензию, передать аудиозапись управляющему салона, связаться с клиентом в течение 2 часов.
- При невыполненных обещаниях: автоматически создать напоминание о звонке или отправке материалов.

#### Шаг 7. Сохранение, аудит 152-ФЗ и уведомления
- Генерируется электронная запись согласия (`consent_id`) в модуле `ConsentLog`.
- Данные атомарно записываются в файл базы данных.
- При оценке ниже 6 баллов или флаге `is_dispute = true` система моментально отсылает тревожное сообщение управляющему в VK Мессенджер или Telegram.

## 6. Безопасность, хранение и защита данных (152-ФЗ РФ)

Приложение спроектировано в строгом соответствии с требованиями Федерального закона РФ № 152-ФЗ «О персональных данных»:

### 6.1. Разграничение доступа к ПДн (RBAC)
- **Только роль «Администратор»** имеет техническую возможность видеть полные номера телефонов клиентов и исходные системные токены.
- Для ролей «Управляющий», «Оператор» и «Наблюдатель» номера телефонов клиентов принудительно маскируются на уровне бэкенда (`maskPhone()`), исключая утечку клиентской базы при просмотре интерфейса или скриншотах.

### 6.2. Шифрование базы данных
- Локальная база данных `data-store.json` шифруется алгоритмом **AES-256-GCM** при наличии ключа `STORE_ENCRYPTION_KEY`.
- Каждый сеанс записи использует уникальный вектор инициализации (IV, 12 байт) и формирует тег аутентификации (Auth Tag, 16 байт) для предотвращения несанкционированного изменения файла на диске.

### 6.3. Электронный журнал учета согласий
- В системе ведется неотчуждаемый реестр согласий на обработку биометрии и аудиозапись разговоров.
- Каждому звонку присваивается уникальный `consent_id` (UUIDv4) с фиксацией метода получения (*голосовое информирование в начале вызова*), даты и перечня целей обработки.
- Реализована функция отзыва согласия с обезличиванием исторической записи.

### 6.4. Сетевая безопасность и доверенные сертификаты
- Все внешние запросы к шлюзам Сбера (`ngw.devices.sberbank.ru:9443`) и МегаФона защищены российскими корневыми сертификатами **Russian Trusted Root CA (Минцифры РФ)**, инсталлируемыми в системное хранилище контейнера на этапе сборки Docker.

### 6.5. Резервное копирование в S3 Timeweb Cloud
- Модули `s3-sync.ts` и `object-storage.ts` обеспечивают регулярную выгрузку резервных копий базы данных в независимое российское объектное хранилище (S3 Timeweb Cloud, Санкт-Петербург/Москва) с шифрованием архивов.

## 7. Генерация отчетов и экспорт данных

Система предоставляет два взаимодополняющих формата управленческой отчетности:

### 7.1. Экспорт в CSV (Microsoft Excel)
- **Стандарт**: RFC 4180 с добавлением сигнатуры **UTF-8 BOM (`\uFEFF`)** в начало файла. Это гарантирует, что русский Excel любой версии открывает кириллические символы корректно без «кракозябр».
- **Разделитель**: точка с запятой (`;`), принятая в российской локали Excel.
- **Содержимое**: ID вызова, дата/время, имя оператора, маскированный телефон, статус записи, услуга, дата визита, время, мастер, балл ИИ, пересказ, выводы и перечень задач Next Steps.
- **Поддержка фильтрации**: если на экране применены фильтры (например, выбран оператор «Анна» за «Этот месяц»), CSV выгружает ровно отфильтрованный срез данных.

### 7.2. Экспорт в PDF (Официальный отчет управляющего)
- **Формат**: Альбомный лист А4 (PDF версии 1.3).
- **Типографика**: Встроенные векторные шрифты `LiberationSans-Regular` и `LiberationSans-Bold` с полной поддержкой кириллицы.
- **Структура документа**:
  1. Фирменный заголовок с названием салона красоты (динамически берется из настроек).
  2. Дата формирования, период и данные ответственного лица.
  3. **Блок ключевых показателей (KPI)**:
     - Всего звонков в выборке;
     - Конверсия в запись (%);
     - Средний балл качества работы персонала;
     - Количество спорных и конфликтных ситуаций.
  4. Таблица реестра звонков с цветовой индикацией статусов.
  5. Официальный блок согласования и подписи управляющего салона.

## 9. Подсистема задач «Next Steps» и всплывающих напоминаний

### 9.1. Назначение подсистемы
Подсистема **Next Steps** преобразует аналитические выводы ИИ в прикладные операционные поручения для дежурного администратора салона. Это исключает потери клиентов при обещаниях «перезвонить через 15 минут», «отправить реквизиты для предоплаты», «уточнить время у топ-мастера» или зафиксировать запись в расписании.

### 9.2. Архитектура и REST API
1. **Генерация списка задач**: `POST /api/calls/:id/generate-next-steps`
   - Передает в модель GigaChat стенограмму, ключевые договоренности, выявленные обязательства (`key_facts.promises`), статус записи и имя мастера.
   - Формирует структурированный массив `NextStepItem[]`: `{ id: string, text: string, completed: boolean }`.
2. **Обновление статуса и чек-листа**: `PUT /api/calls/:id/next-steps`
   - Сохраняет изменения при нажатии чекбоксов, отметке всех задач выполненными или ручном добавлении задачи.
   - Записывает аудит-событие в `access_logs`.

### 9.3. Пользовательский интерфейс и компоненты
- **Вкладка «Задачи Next Steps» (`PendingTasksList.tsx`)**:
  - Фильтрует все звонки, у которых `next_steps_items` содержит хотя бы одну невыполненную задачу (`!item.completed`).
  - Отображает бейдж-счетчик звонков в заголовке вкладки.
  - Содержит панель поиска по клиенту, телефону, имени мастера, услуге или тексту задачи.
  - Предоставляет фильтрацию по операторам и стадиям готовности (все / не начаты / в процессе).
  - Интерактивные чекбоксы с мгновенным зачеркиванием текста и фоновой синхронизацией.
  - Кнопки «Открыть звонок», «Отметить все», «Копировать» и поле быстрого добавления задачи.
- **Всплывающее напоминание в правом нижнем углу (`NextStepsReminderToast.tsx`)**:
  - Располагается с абсолютным позиционированием (`fixed bottom-4 right-4 z-[9990]`).
  - Срабатывает автоматически при наличии незавершенных задач, отображает счетчик открытых шагов и превью ближайшей задачи.
  - Включает кнопку отсрочки «+15 мин» (Snooze с записью метки в `sessionStorage`).
  - Поддерживает сворачивание в компактный пульсирующий бейдж («X звонков требуют действий») и полное разворачивание в один клик.

## 10. Модуль «Уточнить контекст у ИИ» (GigaChat AI)

### 10.1. Назначение и сценарии применения
Модуль решает задачу глубокой фактологической проверки и получения персонализированных выжимок по запросу управляющего или администратора через российскую LLM GigaChat:
- **Проверка финансовых условий:** была ли озвучена конкретная цена, согласована ли скидка, в какой банк и в каком объеме запрошена предоплата.
- **Сверка параметров визита:** точная дата, время слота, имя выбранного мастера.
- **Контроль обещаний оператора:** «я перезвоню через час», «отправлю геолокацию в мессенджер», «уточню у технолога».
- **Разбор конфликтных диалогов:** анализ эмоционального фона и выявление скрытых претензий гостя.

### 10.2. Архитектура интеграции и REST API
1. **Эндпоинт:** `POST /api/calls/:id/clarify-context`
   - Тело запроса: `{ "question": "Текст вопроса" }`
   - Обработчик: `clarifyCallContextWithGigaChat` (`src/services/gigachat.ts`)
2. **Протокол взаимодействия с GigaChat:**
   - **URL:** `https://gigachat.devices.sberbank.ru/api/v1/chat/completions`
   - **Аутентификация:** OAuth2 Bearer токен через Сбер ID/GigaChat Auth API (`src/services/gigachat-auth.ts`).
   - **Модель:** `GigaChat:Lite` / `GigaChat:Pro`.
   - **Температура:** `0.2` (максимальная точность цитирования, отсутствие галлюцинаций).
   - **Очередь запросов (Rate Limiting):** вызовы проходят через FIFO очередь `gigaChatQueue` с соблюдением интервалов между запросами.
   - **Резервный контур (Fallback):** при отсутствии авторизационных данных вызов автоматически переключается на локальный экстрактор цитат с явным указанием источника ответа.
3. **Хранение истории уточнений:**
   - Ответы сохраняются в массив `call.context_clarifications` внутри зашифрованного хранилища AES-256-GCM (`data-store.enc`).
   - Формат записи: `{ id, question, answer, model, provider, timestamp, tokens_used }`.

## 11. Настройка системного промпта ИИ в панели администратора

### 11.1. Назначение и функциональные возможности
В панели администратора системы реализован визуальный редактор **Системного промпта для Сбер GigaChat**, позволяющий управляющему тонко настраивать правила семантического анализа звонков, извлечения фактов и форматирования резюме.

Ключевые регламентные директивы промпта:
1. **Строгое написание ФИО специалистов и клиентов с заглавной буквы:**
   - В русском языке любые фамилии, имена и отчества людей всегда начинаются с прописной (заглавной) буквы (`«Елена Валиулова»`, `«Татьяна Валиулова»`, `«Арина Егорова»`, `«Наталья Гуркина»`, `«Кристина»`, `«Анна»`).
   - Если в распознанной речи Yandex SpeechKit имя записано со строчной буквы (`«к егоровой арене»`, `«уволюовой татьяны»`, `«елена валиулова»`), GigaChat обязан привести каждое слово к заглавной букве: `«Егорова Арина»`, `«Валиулова Татьяна»`, `«Елена Валиулова»`.
2. **Категорический запрет подстановки мусорных и разговорных слов:**
   - Исключены ошибки подстановки частиц, предлогов и глаголов в качестве имени мастера (`«Меня Вот»`, `«Записались»`, `«Будете»`, `«Оставьте»`, `«Посмотрим»`, `«Студио»`, `«Вас Плохо»`).
   - Если клиент говорит: *«Здравствуйте, скажите пожалуйста, у меня вот запись на 5 января к Елене Валиуловой?»*, модель отсекает вводный оборот *«у меня вот»* и фиксирует мастера как `«Елена Валиулова»`.
3. **Параметры процедуры, даты и слота времени:**
   - **Услуга:** точное наименование из прайса салона (*«маникюр с покрытием»*, *«педикюр»*, *«макияж»*, *«укладка»*).
   - **Дата:** календарная дата визита (*«8 ноября»*, *«5 января»*, *«завтра»*, *«в субботу»*).
   - **Время:** строгий формат `ЧЧ:ММ` (*«15:00»*, *«19:00»*, *«13:00»*, *«18:30»*), с преобразованием устного счета (*«15 0 0» → «15:00»*).

### 11.2. REST API эндпоинты управления промптом
- `GET /api/admin/credentials` — возвращает активный `customSystemPrompt` и актуальный заводской эталон `defaultSystemPrompt`.
- `POST /api/admin/credentials` — сохраняет измененный системный промпт в зашифрованное хранилище `data-store.enc` (поле `store.config.customSystemPrompt`).
- `GET /api/admin/default-system-prompt` — отдает эталонный заводской промпт с автоматической подстановкой текущего бренда салона.
- `POST /api/admin/reset-system-prompt` — сбрасывает пользовательский промпт к заводскому эталону с фиксацией в аудит-логе безопасности 152-ФЗ.

### 11.3. Конвейер применения в ядре аналитики
При каждом вызове анализа звонка (`analyzeCallTextOrAudio`, импорт через вебхук или фоновая перепроверка):
1. Сервер считывает `customPrompt = db.config?.customSystemPrompt || db.config?.credentials?.customSystemPrompt`.
2. Передает его в `analyzeWithRetry(..., customPrompt)`.
3. `analyzeWithGigaChat` формирует системное сообщение:
   ```typescript
   const systemPromptContent = (customSystemPrompt && customSystemPrompt.trim().length > 30)
     ? customSystemPrompt.trim()
     : (customSalonName ? getSystemPrompt(customSalonName) : SYSTEM_PROMPT);
   ```
4. Если пользовательский промпт пустой, автоматически используется встроенный эталон `getSystemPrompt(salonName)`.
